# Working Preferences

- For feature or design changes, focus on implementation quality, UI/design quality, and relevant code quality.
- Do not run Android Doctor, Expo Doctor, or broad/unrelated checks unless the user explicitly requests them or the requested change directly requires them.
- Keep verification narrowly scoped to the files and behavior changed; avoid unnecessary audits, exploratory checks, and token-heavy detours.
- Once the requested work is implemented and proportionately verified, stop. Do not continue with optional investigation or polish outside the requested scope.
- Final responses should be concise: summarize what changed, the relevant verification performed, and any action the user must take. Omit process narration and unnecessary detail.
