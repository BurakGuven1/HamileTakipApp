# Personalized Daily Retention and Welcome Email Design

## Goal

Give each mother a useful reason to open Anne+ every day without repetitive or guilt-based engagement. Pregnancy and postpartum users receive different weekly check-ins, daily cards, and 10:00 Europe/Istanbul notifications. New users receive one warm onboarding email after completing onboarding.

## Product Principles

- The weekly check-in and one useful daily card are free.
- Premium sells deeper history, trends, planning, and PDF summaries after value is shown.
- No diagnosis, generated medical advice, guilt streaks, or sensitive lock-screen copy.
- Free-text answers never enter notifications or analytics properties.
- Daily content is curated and rules-based; it is not generated by an LLM.

## Weekly Check-in

The home screen shows a prominent, dismissible `Bu hafta nasılsın?` card on the first eligible visit of each ISO week. It contains three or four tap-first questions and at most one optional short note of 160 characters. Completing it prevents it from appearing again that week. Dismissing it turns it into a quiet home card rather than repeatedly opening a modal.

Question packs rotate for at least eight weeks. Pregnancy packs use gestational week plus themes such as energy, sleep, physical comfort, mood, preparation, and support. Postpartum packs use baby age plus rest, recovery, feeding routine, care load, mood, and family support. High-risk selections return curated safety guidance and appropriate professional-care direction; they never diagnose.

## Daily Experience

Each weekly response produces stable focus tags. A deterministic content engine combines life stage, gestational week or baby age, focus tags, day of week, and recent card history. It returns one daily card with:

- a short personalized insight;
- one concrete action taking roughly one minute;
- a relevant fact for the pregnancy week or baby's age;
- one destination inside the existing app;
- an optional Premium preview when a deeper feature is relevant.

The seven-day rotation deliberately varies between insight, action, education, self-care, family support, tool discovery, and weekly reflection. A user must not receive the same content identity within the configured cooldown window.

The home card has one primary CTA and clear completed, loading, empty, and error states. Notification navigation opens this exact card.

## Premium Boundary

Free users receive the weekly check-in, daily basic card, stage-specific fact, and basic app direction. Premium users additionally receive multi-week comparisons, personal trends, a detailed weekly plan, check-in history, and a doctor-ready PDF summary. A paywall opens only when the user taps a locked detailed insight, history, plan, or PDF CTA; check-in completion itself never triggers a paywall.

## Notifications

The existing `send-daily-support` Supabase Edge Function and Expo Push path remain the delivery system; Firebase is not required. The cron schedule moves from 12:00 to 10:00 Europe/Istanbul (07:00 UTC while Turkey remains UTC+3). Only users with push permission, an enabled token, and `notify_daily_support = true` are eligible. If today's card was already opened before dispatch, the notification is skipped.

Pregnancy and postpartum copy are distinct and reference only safe, non-sensitive context. The push deep-links to the daily card. Delivery, open, card view, action completion, Premium CTA, paywall, and conversion events use existing analytics conventions and contain no names, answers, notes, baby IDs, or medical text.

## Data and Server Boundaries

New tables store versioned question packs, structured weekly responses, optional encrypted/private notes, generated daily card assignments, card completion, and delivery state. RLS restricts mothers to their records; family members do not see maternal answers or notes. Server functions own content selection, weekly uniqueness, daily deduplication, and notification eligibility. Client APIs only read the current experience and submit validated selections.

The daily assignment is created idempotently per owner and Turkey calendar date. Weekly responses are unique per owner, life stage, and ISO week. Life-stage changes close the old plan and start the correct pack without mixing pregnancy and postpartum data.

## Welcome Email

Welcome delivery starts when `profiles.onboarding_completed` first changes to true, not merely when an unused Auth account is created. A unique delivery row per user prevents duplicates and supports retry/audit states without storing email addresses in analytics.

A Supabase Edge Function sends responsive Turkish HTML and plain text through a production email provider such as Resend. Supabase's default SMTP is not used for arbitrary production email. Required server-only configuration includes the provider API key, verified sender/domain, and a dispatch secret.

Every completed onboarding receives a service-oriented welcome email containing:

- a warm Anne+ greeting;
- the pregnancy or postpartum experience available to that user;
- a concise list of free features;
- one safe `Uygulamayı aç` CTA;
- support and privacy links.

Direct Premium purchase language and a Premium CTA appear only when a separate, explicit email marketing consent timestamp exists. The existing `notify_premium_offers` push preference is not reused as email consent. Users without email marketing consent still receive the non-promotional onboarding message. Marketing mail includes sender identity and an unsubscribe path.

## Reliability and Safety

- All weekly, daily, push, and email writes are idempotent.
- Provider failures retain a retryable state with bounded retry attempts.
- Invalid or missing content falls back to a curated stage-specific card.
- Optional notes are excluded from push, email, logs, and raw analytics.
- Safety guidance is curated, versioned, and tested; it does not replace clinical care.
- Existing notification and premium preferences continue to work.

## Measurement

Measure D1/D7/D30 retention by life stage and exposure cohort, weekly check-in completion, daily-card open/completion, notification delivery/open, Premium detail taps, paywall presentation, purchase conversion, welcome-email delivery, and email CTA opens. Compare users only after sufficient cohort time; RevenueCat first/last webhook timestamps are not app-retention signals.

Success means daily value rises without notification opt-outs, repeated content, privacy leakage, or a drop in onboarding completion.

## Verification

- Unit tests cover pack rotation, stage separation, daily uniqueness, Premium boundaries, notification eligibility, email rendering, consent filtering, and idempotency.
- SQL tests cover RLS, weekly/daily unique constraints, lifecycle transitions, and one-time welcome delivery.
- Edge Function tests cover fallback content, dispatch deduplication, retry behavior, and secret validation.
- Focused TypeScript and Deno checks run without broad Expo/Android doctor commands.
- Acceptance tests cover pregnancy and postpartum first-week flows, a returning week, a pre-10:00 card open, locked Premium insight, onboarding welcome email, and consented versus non-consented email content.
